为什么有效？Groq 的访问限制基于来源 IP。函数在境外执行，请求从境外发起，自然不再被拒。
为什么安全？代理只转发白名单请求头，不保存 Key、不落库对话；你的 Key 只出现在请求的 Authorization 头里。

可选环境变量

← 左右滑动查看完整表格 →

变量必填说明
GROQ_UPSTREAM_BASE否上游地址，默认 https://api.groq.com/openai/v1；必须是 OpenAI 兼容前缀。
RELAY_PASSWORD否设置后所有代理请求必须带 x-relay-password 头，防止域名被扫描滥用。
ALLOWED_ORIGINS否允许跨域的来源，逗号分隔；默认 *。填自己站点可收紧。
UPSTREAM_TIMEOUT_MS否等待上游响应头的超时（1000–58000），默认 55000。

环境变量修改后需要重新部署（Deploys → Trigger deploy）才会生效。

FAQ

常见问题

为什么中国大陆访问不了 Groq？

Groq 按来源 IP 做地区限制，中国大陆网络直连 api.groq.com 通常超时或被拒绝。本代理让请求从 Netlify 美国节点发出，从而恢复正常。

我的 API Key 安全吗？

Key 只保存在你浏览器的 localStorage 里。每次请求放在 Authorization: Bearer … 头中，经 Netlify 函数原样透传给 Groq。代理代码不写日志、不落库、不做任何缓存。前端与函数代码都在仓库里，可自行审计。

注册 Groq 账号还需要翻墙吗？

需要一次。代理只能解决 API 调用阶段的网络可达性；注册、验证、充值等网页操作仍需你自行解决网络问题。拿到 Key 之后，日常调用就都可以走本站了。

会不会被陌生人刷爆？

默认 BYOK 公开模式：任何人用你的代理都必须携带自己的 Key，消耗的是他们自己的 Groq 额度。若担心 Netlify 调用额度被白白消耗，在 Netlify 环境变量里设置 RELAY_PASSWORD，页面会自动要求填写访问密码。

和 Cloudflare Workers 方案相比呢？

思路完全相同：在境外边缘/函数节点做透明转发。Cloudflare 免费额度更大，本方案按需求部署在 Netlify。两边的函数代码都只有一两百行，迁移成本很低。

为什么不用 Netlify 的 redirect 代理？

纯 redirect 代理会被 CDN 层缓冲 SSE 流，聊天会“卡住半天后一次性出现”，且无法自定义 CORS、密码与错误格式。本方案用 Functions 透传流式 body，体验与直连一致。

Netlify 站点本身在国内访问稳定吗？

Netlify 没有中国大陆节点，通常可访问但延迟因运营商而异。建议绑定自己的域名并观察实际线路；如果本地访问不稳，可把同一份代码部署到 Cloudflare Pages 等其它平台。

都支持哪些端点？

Groq 的全部 OpenAI 兼容端点：/chat/completions、/models、/audio/transcriptions、/audio/translations、/embeddings、/audio/speech 等，以 Groq 上游实际提供为准。
